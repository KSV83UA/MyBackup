# MyBackup — архитектура

Резервное копирование RDP-сервера с 1С по нестабильному каналу связи:
базы 1С (файловые и SQL), профили пользователей, выбранные папки и файлы.
Управление через веб-интерфейс, уведомления и команды через Telegram.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Движок копирования | **restic** (BSD-2) | Докачка описана в документации (индекс пишется периодически, повторный запуск отправляет только недостающее); `--stdin-from-command` сам проверяет код возврата дампа; JSON-вывод для интеграции; дедупликация, сжатие, шифрование, VSS |
| Программа | **Одна служба Windows на .NET 10** со встроенным веб-интерфейсом и Telegram-ботом | Нет связки «окно + служба»; на терминальном сервере не появляется значок в трее у каждого пользователя; веб-интерфейс доступен удалённо через VPN; позже вырастает в центральную панель для нескольких серверов |
| Хранилище | Любое из поддерживаемых restic | См. раздел «Хранилища» |
| Образ системы | **Вне MyBackup**, отдельным инструментом по типу сервера | Файловый движок не восстанавливает загрузчик и разделы; MyBackup только собирает статус образа в общий отчёт (этап 3) |

## Компоненты

```
MyBackup.Service  (служба Windows, LocalSystem)
 ├─ Scheduler        расписание задач (cron)
 ├─ JobRunner        выполняет задачу по шагам, повторы, итоговый отчёт
 ├─ Sources          что копируем
 │   ├─ FileBase1C       файловые базы 1С (VSS)
 │   ├─ MsSql            базы MS SQL (BACKUP → restic, по одной)
 │   ├─ PostgreSql       базы PostgreSQL (pg_dump потоком в restic)
 │   ├─ UserProfiles     профили пользователей без системных
 │   ├─ CustomPaths      произвольные папки и файлы, маски
 │   └─ OneCService      лицензии 1С, настройки кластера, ibases.v8i
 ├─ ResticEngine     запуск restic.exe, разбор JSON, повторы с паузой
 ├─ Telegram         уведомления + команды /status /run /last
 ├─ History          журнал запусков
 ├─ ConfigStore      настройки: сохранение из веб-интерфейса без перезапуска службы
 └─ WebUI            веб-интерфейс, по умолчанию только localhost; отдельное приложение внутри
                     службы — его сбой (занят порт) не останавливает копирование

MyBackup.Core       вся логика (библиотека, покрыта тестами)
MyBackup.Web        веб-сервер (ASP.NET Core) и интерфейс; HTML/JS/CSS встроены в сборку,
                    без внешних библиотек и CDN — сервер может быть без интернета
```

## Как копируется каждый тип данных

| Что | Как | Детали |
|---|---|---|
| Файловые базы 1С | `restic backup --use-fs-snapshot` | VSS-снимок, база не останавливается |
| MS SQL | `BACKUP DATABASE … TO DISK WITH COPY_ONLY, CHECKSUM` без сжатия → `RESTORE VERIFYONLY` → restic → удалить `.bak` | Базы по одной: место нужно только под самую большую базу. Без сжатия SQL — тогда restic передаёт только изменённые блоки. `COPY_ONLY` не ломает цепочку существующих планов обслуживания. Этап 2+: поток через VDI без промежуточного файла |
| PostgreSQL | `restic backup --stdin-from-command -- pg_dump -Fc -Z0 …` | На диск ничего не пишется; ошибка дампа прерывает снимок |
| Профили | `ProfileList` в реестре → основные папки с учётом перенаправления | Пропускаем `S-1-5-18/19/20`, служебные профили, `Default`, `Public`; исключаем `AppData\Local`, `Temp`, кеши |
| Свои папки | Пути + маски включения/исключения | `--exclude`, `--iexclude`, `--files-from` |
| Служебное 1С | `C:\ProgramData\1C\licenses`, `srvinfo`, `%APPDATA%\1C\1CEStart\ibases.v8i` | Лицензии после переустановки иначе приходится заново активировать |
| Выгрузка 1С `.dt` | `1cv8.exe DESIGNER /F|/S … /DumpIB файл.dt /Out лог /DumpResult файл` → restic → удалить файл | Успех — код 0, «0» в файле результата и непустой `.dt`; иначе в отчёт идут последние строки журнала Конфигуратора. Тайм-аут против зависания. `.dt` сжат — дедупликации нет, поэтому раз в неделю отдельной задачей |

## Работа с нестабильным каналом

- Обрыв — штатная ситуация: задача повторяется с растущей паузой до конца окна копирования;
  restic не отправляет повторно уже переданные блоки.
- Точность докачки — запись индекса restic, примерно раз в 10 минут (замер на 0.20.0: первый индекс на 11-й минуте;
  после принудительной остановки повторный запуск передал 100 МБ из 256). Всё, что отправлено после последней
  записи индекса, при прерывании уходит повторно. Ctrl+C индекс не сохраняет (проверено), поэтому «мягкая»
  остановка restic не нужна. Короткие обрывы restic переживает сам, повторяя запросы к хранилищу.
- Ограничение скорости в рабочее время (`--limit-upload`), ночью — без ограничения.
- Первую полную копию большой базы можно один раз отвезти на диске.
- Если место на сервере есть — можно держать локальное хранилище для быстрого
  восстановления и отправлять копию наружу отдельно (`restic copy`). Если места нет —
  копия идёт сразу во внешнее хранилище.

## Хранилища

| Хранилище | Адрес restic | Защита от удаления |
|---|---|---|
| Офис / VPS (рекомендуется) | `rest:https://host:8000/repo` | `rest-server --append-only`: с сервера 1С удалить копии нельзя; очистка старых копий — со стороны хранилища |
| S3 | `s3:https://endpoint/bucket/repo` | Версионирование бакета + правила хранения на стороне S3 |
| SFTP | `sftp:user@host:/path` | Только права на стороне сервера |
| Локальный диск / NAS | `D:\restic-repo`, `\\nas\repo` | Нет, только как дополнительная копия |

## Безопасность

- Пароль хранилища и токен Telegram хранятся зашифрованными (DPAPI, LocalMachine).
- Telegram принимает команды только от разрешённых `chat_id`; остальные чаты запоминаются, чтобы их можно было
  разрешить в веб-интерфейсе.
- Веб-интерфейс по умолчанию слушает только `127.0.0.1` (и принимает только имена localhost — защита от
  DNS rebinding). Вход по паролю (PBKDF2, 600 000 итераций), пауза после 5 ошибок, cookie `HttpOnly`,
  `SameSite=Strict` плюс обязательный заголовок `X-MyBackup` у изменяющих запросов (CSRF), строгий CSP.
- Секреты в браузер не уходят: маска `••••••`, при сохранении маска заменяется прежним значением, новые значения
  шифруются. Из браузера не меняются параметры, от которых зависит, что запускается (путь к restic,
  `pg_dump` только с именем `pg_dump.exe`, запрет переменных `*_COMMAND`), и доступ к самому интерфейсу.
- Хранилище по возможности в режиме «только добавление».

## Этапы

1. **Ядро и Telegram** — *сделано (v0.1.0)*. Служба, все типы данных, restic с повторами, уведомления и команды
   в Telegram, настройки в JSON-файле. Восстановление — командой `MyBackup restic restore`.
2. **Веб-интерфейс** — *сделано (v0.2.0)*. Сводка с ходом копирования и остановкой задачи, задачи и источники
   (дерево папок сервера с галочками и исключениями, поиск баз 1С, проверка SQL и прав на BACKUP, профили
   с предпросмотром), расписание, журнал, снимки с командой восстановления, настройки хранилища, скорости,
   Telegram (разрешение чатов из интерфейса), смена пароля. Предупреждение «давно не было успешной копии»
   на сводке. Команда `/stop` в Telegram.
   *v0.2.1:* выгрузка 1С в `.dt` (источник «Выгрузка 1С»), просмотр снимка по папкам и скачивание из браузера
   (файл — как есть, папка — zip через `restic dump --archive zip "снимок:родитель" /папка`).
   *Перенесено:* поток MS SQL через VDI без промежуточного файла — его нужно проверять на настоящем SQL Server.
3. **Восстановление и контроль.** «Вернуть базу на дату», «вернуть файл пользователю»,
   пробное восстановление по расписанию, тревога «давно не было копии» в Telegram,
   статус образа системы в общем отчёте.

## Открытые вопросы

- MS SQL или PostgreSQL — поддерживаем оба.
- Версия Windows Server: для .NET 10 проверить по официальной таблице поддерживаемых ОС
  (2012/2012 R2 — под вопросом).
- Инструмент для образа системы зависит от типа сервера (физический, Hyper-V, Proxmox, VPS).
