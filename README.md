# MyBackup

Резервное копирование RDP-сервера с 1С по нестабильному каналу связи. Служба Windows на .NET 10,
движок копирования — [restic](https://restic.net). Управление — веб-интерфейс на самом сервере, отчёты
и команды — Telegram. Архитектура и принятые решения — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Что копирует:

| Источник | Как |
|---|---|
| Файловые базы 1С | VSS-снимок папки с `1Cv8.1CD`, без остановки базы; временные файлы и полнотекстовый индекс исключаются |
| MS SQL | `BACKUP DATABASE … COPY_ONLY, CHECKSUM` без сжатия → проверка `RESTORE VERIFYONLY` → restic → файл удаляется. Базы по одной |
| PostgreSQL | `pg_dump` потоком прямо в restic, на диск ничего не пишется |
| Профили пользователей | Рабочий стол, Документы, Загрузки, Изображения, Избранное всех пользователей, кроме системных |
| Папки и файлы | Выбор в дереве папок сервера, исключения по пути и по маске |
| Служебные файлы 1С | Лицензии, реестр кластера (`srvinfo\*.lst`), списки баз пользователей |
| Выгрузка 1С (`.dt`) | Конфигуратор в пакетном режиме (`/DumpIB`) для файловой или серверной базы → restic → файл удаляется |

Обрыв связи — штатная ситуация: задача повторяется с растущей паузой, restic не передаёт заново уже
отправленные блоки. После первой полной копии передаются только изменения.

## Сборка

Нужен .NET 10 SDK и `restic.exe` в `tools\restic\` (скачивается с
[github.com/restic/restic/releases](https://github.com/restic/restic/releases)).

```powershell
dotnet test
dotnet publish src/MyBackup.Service -c Release -o publish
```

В `publish\` получится `MyBackup.exe` (один файл, .NET на сервере ставить не нужно; веб-интерфейс внутри),
`restic.exe`, `config.example.json` и `install-service.ps1`.

## Установка на сервер

1. Скопируйте папку `publish` на сервер и выполните в PowerShell от администратора:
   ```powershell
   .\install-service.ps1
   ```
   Скрипт ставит программу в `C:\Program Files\MyBackup`, создаёт `C:\ProgramData\MyBackup\config.json`
   из примера (доступ только у SYSTEM и администраторов), спрашивает пароль веб-интерфейса и запускает службу.
2. Откройте на сервере (в сеансе RDP) **http://127.0.0.1:8480** и войдите.
3. «Настройки → Хранилище»: адрес и пароль хранилища → «Сохранить» → «Проверить хранилище» → «Создать хранилище».
   **Пароль хранилища сохраните отдельно от сервера** — без него копии не восстановить.
4. «Задачи»: расписание и что копировать (базы 1С можно найти кнопкой «Найти базы 1С на сервере»).
5. «Настройки → Telegram»: токен бота, затем напишите боту — чат появится в списке, нажмите «Разрешить».
6. «Сводка» → «Запустить сейчас» и посмотрите отчёт в «Журнале».

Всё то же можно сделать без браузера: заполнить `config.json` вручную (пароли — через `MyBackup.exe protect`)
и выполнить `check`, `init`, `run` — см. «Команды».

## Веб-интерфейс

| Раздел | Что там |
|---|---|
| Сводка | Что выполняется сейчас (этап, процент, повторы после обрывов), кнопки «Запустить» и «Остановить», следующий запуск, предупреждения: давно не было успешной копии, ошибки в настройках, VSS недоступен |
| Задачи | Расписание (каждый день / по дням недели / каждые N часов / cron) с ближайшими запусками; источники: дерево папок сервера с галочками, поиск баз 1С, проверка подключения к SQL Server и прав на BACKUP, выбор пользователей и папок профиля с предпросмотром; правила хранения |
| Журнал | Отчёты о запусках с подробностями по каждой базе и папке; журнал службы |
| Снимки | Копии в хранилище по источникам; «Файлы» — просмотр снимка по папкам и скачивание (файл как есть, папка — zip-архивом); «Команда» — готовая команда восстановления |
| Настройки | Хранилище (проверка, создание), ограничение скорости днём и ночью, повторы, Telegram, смена пароля |

Изменения применяются после «Сохранить» без перезапуска службы; выполняемая задача доработает со старыми настройками.

**Доступ.** По умолчанию интерфейс открывается только на самом сервере (`http://127.0.0.1:8480`).
Для доступа по сети — лучше через VPN — укажите в `config.json`:

```jsonc
"web": { "urls": [ "https://0.0.0.0:8443" ], "certificatePath": "C:\\ProgramData\\MyBackup\\web.pfx", "certificatePassword": "dpapi:..." }
```

и перезапустите службу. Если порт занят или сертификат не читается, копирование продолжает работать,
а ошибка уходит в журнал и Telegram.

**Безопасность.**
- Пароль хранится в виде хеша PBKDF2 в `C:\ProgramData\MyBackup\web-password`. После 5 неверных попыток
  с одного адреса — растущая пауза. После смены пароля другие открытые сеансы завершаются.
- Пароли хранилища, токен Telegram, пароли SQL и PostgreSQL в браузер не передаются (вместо них `••••••`);
  новые значения шифруются DPAPI при сохранении.
- Из браузера нельзя изменить имя сервера, папку данных, адреса веб-интерфейса, путь к restic и адрес API Telegram,
  а переменные окружения restic вида `*_COMMAND` запрещены — правка настроек не позволяет запустить
  произвольную программу от имени службы.
- Забыли пароль: `MyBackup.exe web-password` от имени администратора.

**Файл настроек.** При сохранении из браузера `config.json` переписывается целиком: комментарии не сохраняются,
прежняя версия остаётся в `C:\ProgramData\MyBackup\config-backups` (последние 30). Если файл правили вручную после
запуска службы, сохранение из браузера будет отклонено — перезапустите службу, чтобы не потерять правку.

## MS SQL: права службы

Служба работает от имени SYSTEM. При `Integrated Security=true` в SQL Server 2012 и новее у этой учётной записи
по умолчанию **нет** прав на `BACKUP DATABASE`. Кнопка «Проверить подключение» покажет, на какие базы прав нет.
Проще всего выполнить в SQL Server Management Studio:

```sql
ALTER SERVER ROLE [sysadmin] ADD MEMBER [NT AUTHORITY\SYSTEM];
```

Либо используйте в строке подключения отдельный SQL-логин с правами на копирование (пароль будет зашифрован).

## Выгрузка 1С (.dt)

Источник «Выгрузка 1С (.dt)» запускает Конфигуратор в пакетном режиме:
`1cv8.exe DESIGNER /F <папка базы> | /S <сервер\база> /N <пользователь> /P <пароль> /DumpIB <файл.dt>`.
Файл сохраняется во временную папку, отправляется в хранилище и удаляется; журнал Конфигуратора попадает в отчёт при ошибке.

- Нужна установленная платформа 1С. По умолчанию берётся самая новая из `Program Files\1cv8\<версия>\bin\1cv8.exe`
  (в «Дополнительно» видно, какая найдена) — или укажите путь к `1cv8.exe`.
- Если в базе есть пользователи, укажите пользователя с правами администратора (пароль хранится зашифрованным).
- Служба работает от имени SYSTEM: Конфигуратору нужна лицензия, доступная на этом компьютере
  (программная лицензия на сервере или ключ).
- Файл `.dt` сжат, поэтому при каждом запуске передаётся целиком, а не только изменения. Удобно сделать отдельную
  задачу «раз в неделю» только с выгрузкой, а каждый день копировать базы источником «Файловая база 1С».
- Если Конфигуратор завис (например, ждёт ответа в окне), выгрузка прерывается через 3 часа (настраивается).
- Восстановление: скачайте `.dt` («Снимки» → «Файлы»), затем в Конфигураторе пустой базы:
  «Администрирование → Загрузить информационную базу».

## Хранилище

Рекомендуется [rest-server](https://github.com/restic/rest-server) в офисе или на VPS в режиме
«только добавление» — с сервера 1С (и шифровальщику на нём) удалить копии нельзя:

```
rest-server --path /srv/restic --append-only --private-repos --htpasswd-file /srv/restic/.htpasswd --tls --tls-cert cert.pem --tls-key key.pem
```

Адрес: `rest:https://rdp1c:ПАРОЛЬ@backup.example.ru:8000/rdp1c/` — в веб-интерфейсе пароль внутри адреса
скрывается и шифруется. Старые копии в этом режиме удаляются на стороне хранилища (по расписанию, с прямым
доступом к папке):

```
restic -r /srv/restic/rdp1c forget --group-by host,tags --keep-daily 7 --keep-weekly 4 --keep-monthly 12 --prune
```

Также подходят S3 (`s3:https://…`, ключи — в переменных окружения в «Настройки → Хранилище»), SFTP и диск/NAS.

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather).
2. «Настройки → Telegram»: включите, вставьте токен, сохраните.
3. Напишите боту любое сообщение, нажмите «Обновить» — чат появится в «Писали боту»; «Разрешить» → «Сохранить».
4. «Отправить проверочное сообщение».
5. Если `api.telegram.org` недоступен напрямую — укажите прокси `socks5://host:port`.

Команды бота (только из разрешённых чатов): `/status`, `/last`, `/run [задача]`, `/stop`, `/jobs`, `/help`.

## Команды

| Команда | Что делает |
|---|---|
| `MyBackup.exe` | Служба (при запуске из консоли — работает в консоли для отладки) |
| `check` | Проверить настройки, restic, хранилище, Telegram, пароль веб-интерфейса |
| `init` | Создать хранилище |
| `run [задача]` | Выполнить задачу сейчас |
| `snapshots [имя]` | Список снимков |
| `profiles` | Какие профили и папки пользователей будут скопированы |
| `protect <текст>` | Зашифровать пароль для `config.json` |
| `web-password` | Задать пароль веб-интерфейса |
| `telegram-test` | Проверить бота / узнать `chat_id` |
| `restic <аргументы>` | Любая команда restic с настройками хранилища |

Ко всем командам можно добавить `--config путь\config.json`.

## Восстановление

**Проще всего — из браузера:** «Снимки» → нужный источник → дата → «Файлы». Откроется содержимое копии по папкам;
«Скачать» сохраняет файл как есть, «zip» — папку архивом (в папку загрузок браузера). Так восстанавливаются
отдельные файлы пользователей, файл `.bak` базы SQL, дамп PostgreSQL и выгрузка `.dt`.

**Большие объёмы** (вся файловая база, много папок) удобнее восстанавливать командой: кнопка «Команда» у снимка
даёт готовую команду для PowerShell. Вручную:

```powershell
# какие копии есть
MyBackup.exe snapshots Бухгалтерия

# файловая база 1С на дату: содержимое папки базы — в D:\Restore\Buh
MyBackup.exe restic restore "latest:/D/1C/Buh" --tag "name:Бухгалтерия" --target D:\Restore\Buh
MyBackup.exe restic restore "3f2a9c1e:/D/1C/Buh" --target D:\Restore\Buh      # конкретный снимок

# база MS SQL: файл .bak, затем RESTORE DATABASE в SQL Server
MyBackup.exe restic restore latest --tag "name:UT" --target D:\Restore\sql

# база PostgreSQL: файл дампа, затем pg_restore
MyBackup.exe restic dump latest /zup.pgdump --tag "name:zup" --target D:\Restore\zup.pgdump

# один файл пользователя (dump, а не restore --include: тот воссоздаёт цепочку папок C\Users\… с их правами)
MyBackup.exe restic dump latest --tag "name:Профили пользователей" "/C/Users/ivanov/Desktop/Отчёт.xlsx" --target D:\Restore\Отчёт.xlsx
```

Подробнее о командах restic — [docs/RESTIC.md](docs/RESTIC.md).

## Ограничения текущей версии

- Копия файловой базы через VSS согласована «как при выключении питания». Для надёжности регулярно
  делайте пробное восстановление и добавьте выгрузку `.dt` раз в неделю.
- Выгрузка `.dt` проверена с имитацией Конфигуратора; с настоящей платформой 1С — ещё нет.
- Перенаправленные папки профиля (например, «Документы» на диске D:) видны только у пользователей,
  которые сейчас в системе; у остальных берётся стандартная папка внутри профиля.
- Для MS SQL нужно место под копию самой большой базы. Передача потоком без промежуточного файла — в следующих этапах.
- SQL Server на другом сервере: укажите `backupDirectory` как общую папку, доступную обоим.
- restic записывает сведения об отправленных данных (индекс) примерно раз в 10 минут. Если отправку прервать
  (кнопка «Остановить», смена ограничения скорости утром и вечером, остановка службы, долгий обрыв связи),
  повторно уйдёт то, что передано после последней записи индекса, — не больше ~10 минут работы
  (при 8 Мбит/с — до ~600 МБ). Проверено на restic 0.20.0: после остановки на 11-й минуте повторный запуск
  передал 100 МБ из 256; Ctrl+C вместо принудительной остановки индекс не сохраняет. Короткие обрывы связи
  restic переживает сам, не прерывая отправку.
- Восстановление на место кнопкой («вернуть базу на дату») — этап 3; сейчас — скачивание из «Снимков» или командой.
- Образ системы делается отдельным инструментом.
